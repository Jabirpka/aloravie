# Aloravie Mobile (Flutter)

The Android + iOS storefront for Aloravie, sharing the same backend API as the web store. Built with Flutter, in the Aloravie brand (terracotta + cream, Jost, light + Evening/dark).

## What's here

`lib/` holds the full app:
- **Shopping**: home, shop (with category filter), product detail, cart — all wired to `/api/products`, with a sample catalogue fallback so it runs before the backend is up.
- **Account**: sign in / create account, profile, sign out (customer auth, tokens in `SharedPreferences`).
- **Checkout**: address form → places a real order via `/api/checkout` and confirms it in mock-payment mode.
- **Orders**: order history and an order detail screen with a **live tracking timeline**.
- **Notifications**: on-device notifications on order events (`lib/services/notifications.dart`).

## First run

This repo contains the Dart source (`lib/`), `pubspec.yaml`, and config. The platform folders (`android/`, `ios/`) are generated by Flutter:

```bash
cd mobile
flutter create .        # generates android/ + ios/ (keeps lib/ and pubspec.yaml)
flutter pub get
flutter run             # with a device/emulator attached
```

Point the app at your backend (defaults to `http://10.0.2.2:4000`, the Android-emulator alias for localhost):

```bash
flutter run --dart-define=API_URL=http://10.0.2.2:4000
```

> Requires the Flutter SDK (`>=3.22`). The source wasn't run through `flutter analyze` where it was written (no SDK there) — run it once after `flutter pub get`.

## Remote push (FCM) — production step

The app ships **local** notifications (they fire on order events). To notify customers when the app is closed, add Firebase Cloud Messaging:

1. Create a Firebase project; add the Android and iOS apps.
2. Add `google-services.json` (`android/app/`) and `GoogleService-Info.plist` (`ios/`). Both are gitignored.
3. Add `firebase_core` + `firebase_messaging` to `pubspec.yaml`; run `flutterfire configure`.
4. In `lib/services/notifications.dart`, initialise Firebase, request permission, get the FCM token and POST it to the backend (add a `POST /api/customers/me/push-token` endpoint), and forward `FirebaseMessaging.onMessage` to `show(...)`. Send a push from the backend when an order's status changes (hook into the fulfilment sync).

`lib/services/notifications.dart` has these steps as a comment next to the code.

## Payments on mobile

Checkout runs end to end in `PAYMENT_MODE=mock`. For live payments add the `razorpay_flutter` plugin and open the Razorpay checkout in `checkout_screen.dart` where the mock branch is (the backend already creates the Razorpay order and verifies the signature).
